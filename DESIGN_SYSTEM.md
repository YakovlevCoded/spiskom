# Дизайн-система «Списком»

Документ описывает визуальный язык, UI-примитивы и правила расширения библиотеки компонентов.

## Бизнес- и UI-логика

Логика компонента делится на два слоя.

| Слой | Где | Ответственность |
| --- | --- | --- |
| UI-логика | `components/**/use-*.ts` | Состояние формы, открытие диалога, локальные обработчики, навигация |
| Бизнес-логика | `src/hooks/**/*.ts` | Загрузка данных, мутации, бизнес-правила, вызовы `src/api` |
| HTTP-клиент | `src/api/**/*.ts` | `fetch`, базовый URL, разбор ошибок |

Правила:

- UI-хук может вызывать бизнес-хук.
- Бизнес-хук не знает про JSX, модалки, кнопки и DOM.
- Компонент и страница только рендерят разметку и вызывают хуки.
- `fetch` разрешён в бизнес-хуках и `src/api`.
- `fetch` запрещён в UI-хуках, `.tsx` компонентах и страницах.
- Если компоненту нужны данные, он вызывает бизнес-хук, а не API напрямую.
- Если компоненту нужно локальное поведение, оно выносится в UI-хук рядом с компонентом.

## Принципы

- Спокойный интерфейс без визуального шума.
- Одна главная задача на экран.
- Тёплая светлая палитра, глубокий зелёный акцент.
- Крупная типографика в заголовках, спокойный текст в контенте.
- Компоненты сначала решают задачу, потом украшают.
- Все интерактивные элементы доступны с клавиатуры.

## Токены

Токены заданы в `frontend/src/index.css` и используются через Tailwind-классы.

| Токен | Назначение |
| --- | --- |
| `background` | Тёплый фон приложения |
| `foreground` | Основной графитовый текст |
| `card` | Поверхность карточек и форм |
| `primary` | Глубокий зелёный акцент и основные кнопки |
| `primary-foreground` | Текст на основном акценте |
| `secondary` | Вторичные поверхности и hover |
| `muted` | Приглушённые блоки и скелетоны |
| `muted-foreground` | Вторичный текст |
| `accent` | Мягкая зелёная подсветка |
| `destructive` | Ошибки и удаление |
| `border` | Границы карточек, полей и разделителей |
| `input` | Граница полей ввода |
| `ring` | Фокусное кольцо |

Радиусы: `sm`, `md`, `lg`, `xl`, `2xl`, `3xl`. Базовый радиус — `0.85rem`.

## Типографика

- Шрифт: Manrope, локально через `@fontsource-variable/manrope`.
- Заголовок страницы: `text-4xl` или `text-5xl`, вес 800, tracking `-0.055em`.
- Заголовок карточки: `text-lg` или `text-xl`, вес 800.
- Основной текст: `text-sm` или `text-base`, межстрочный `1.5–1.75`.
- Подписи и метаданные: `text-xs`, вес 600–700.
- Заголовки форм: `text-3xl`, вес 800.

## Отступы и layout

- Базовый шаг — 4px, используются Tailwind-шкалы 2, 3, 4, 5, 6, 8.
- Основной экран: `max-w-5xl`, боковые отступы `px-5 sm:px-8`.
- Формы авторизации: `max-w-md`.
- Карточки: padding `p-5` или `p-6`, на больших экранах `sm:p-8`.
- Между блоками — 24–32px, между полями формы — 20px.
- Мобильный вид первичен. Никаких горизонтальных скроллов.

## Поверхности

- Основная карточка: `rounded-2xl` или `rounded-[1.75rem]`, `border`, `bg-card`.
- Hero-блок: крупный радиус, мягкая тень, лёгкий градиент.
- Интерактивная карточка: подъём на 1–2px при hover, без резких анимаций.
- Пустое состояние: пунктирная граница, центральная иконка, короткий текст.

## Компоненты

### Button

Файл: `frontend/src/components/ui/button.tsx`.

Варианты:

- `default` — основное действие.
- `outline` — вторичное действие и отмена.
- `ghost` — иконки, выход, малозаметные действия.
- `destructive` — удаление.

Размеры:

- `default` — основные формы и CTA.
- `sm` — компактные действия в шапке.
- `icon` — квадратная кнопка с иконкой.

Правила:

- Одна основная кнопка на экран или диалог.
- Иконка без текста всегда имеет `aria-label`.
- Во время запроса кнопка disabled и показывает `LoaderCircle`.
- Не менять высоту кнопки вручную, использовать размеры.

### Input, Textarea, Label, Field

Файлы: `frontend/src/components/ui/input.tsx`, `textarea.tsx`, `label.tsx`, `field.tsx`.

- Поле ввода — высота 44px, радиус `rounded-xl`, граница `border-input`.
- Ошибка поля — `aria-invalid` и текст под полем.
- Подпись всегда связана с полем через `htmlFor` и `id`.
- `Field` собирает label, контрол, hint и ошибку.
- Placeholder не заменяет label.
- Ошибки формулируются по-русски и объясняют, что исправить.

### Card

Файл: `frontend/src/components/ui/card.tsx`.

- `Card` — поверхность.
- `CardHeader`, `CardTitle`, `CardDescription`, `CardContent`, `CardFooter` — структура.
- Не вкладывать карточку в карточку без визуальной необходимости.
- Заголовок карточки не дублирует заголовок страницы.

### Checkbox

Файл: `frontend/src/components/ui/checkbox.tsx`.

- Круглый чекбокс 24px.
- Выполненная задача: зелёная заливка, галочка, зачёркнутый заголовок и описание.
- Во время запроса — spinner и disabled.
- `role="checkbox"` и `aria-checked` обязательны.
- `aria-label` объясняет действие: отметить или вернуть в работу.

### Dialog

Файл: `frontend/src/components/ui/dialog.tsx`.

- Основа — нативный `<dialog>` с `showModal`.
- Радиус 24px, ширина до 512px, backdrop с blur.
- Закрытие по Escape, клику по backdrop и кнопке X.
- Заголовок и описание связаны через `aria-labelledby` и `aria-describedby`.
- В диалоге одна основная кнопка.
- Поведение открытия и закрытия — в `use-dialog.ts`.

### Skeleton

Файл: `frontend/src/components/ui/skeleton.tsx`.

- Используется только для загрузки, не для пустого состояния.
- Повторяет геометрию будущего контента.
- Не показывать skeleton дольше реального запроса.

### FormAlert

Файл: `frontend/src/components/ui/form-alert.tsx`.

- Показывает общую ошибку формы.
- Не заменяет ошибки конкретных полей.
- Текст короткий и actionable.

### Link

Файл: `frontend/src/components/ui/link.tsx`.

- Внутренние ссылки идут через `Link` и `preact-iso`.
- Внешние ссылки открываются обычным `<a>`.
- Не стилизовать ссылку как кнопку, если это навигация.

## Состояния

Каждый интерактивный компонент обязан иметь:

- default;
- hover;
- focus-visible;
- disabled;
- loading, если выполняет запрос;
- error, если может завершиться ошибкой.

Экраны обязаны иметь:

- loading;
- empty;
- error;
- success.

## Доступность

- Все поля имеют label.
- Все иконки-кнопки имеют `aria-label`.
- Фокус виден через `focus-visible:ring-*`.
- Минимальная зона нажатия — 40px.
- Цвет не является единственным носителем смысла.
- Ошибки объявляются через `aria-live`.
- Диалог удерживает фокус и закрывается с клавиатуры.
- Контраст текста и фона проверяется визуально.

## Анимации

- Длительность 150–200ms.
- Только `transform`, `opacity`, цвета и тени.
- Без бесконечных декоративных анимаций.
- Spinner используется только во время реального ожидания.

## shadcn/ui и Preact

- Компоненты повторяют структуру и API shadcn/ui.
- `frontend/components.json` хранит конфигурацию shadcn.
- Из-за Preact тяжёлые Radix-зависимости не используются.
- Dialog и Checkbox реализованы нативно, но сохраняют shadcn-стиль и доступность.
- Новый примитив добавляется в `components/ui`, тип props — в `types/ui.ts`, поведение — в `use-*.ts` рядом.

## Как добавить новый компонент

1. Проверить, нет ли готового примитива в `components/ui`.
2. Добавить тип props в `frontend/src/types`.
3. Добавить компонент в `frontend/src/components/ui`.
4. Вынести UI-состояние и эффекты в `use-*.ts` рядом.
5. Вынести загрузку и мутации в бизнес-хук `src/hooks`.
6. Использовать токены, а не произвольные цвета.
7. Проверить hover, focus, disabled, loading и error.
8. Проверить мобильный вид.
9. Запустить `npm run lint`, `npm run typecheck`, `npm run build`.

## Запрещено

- Держать props-типы внутри UI-компонента.
- Вызывать API из компонента или UI-хука.
- Держать `useState`, `useEffect`, `useRef` или `fetch` в `.tsx` компонентах и страницах.
- Держать `fetch` в UI-хуках.
- Импортировать бизнес-контекст в UI-примитив.
- Импортировать UI или страницы в бизнес-хук.
- Использовать случайные hex-цвета вместо токенов.
- Добавлять комментарии в код.
- Делать компонент больше 120 строк для UI-примитива и 180 строк для экрана.
- Создавать «универсальный» компонент без реального второго использования.
